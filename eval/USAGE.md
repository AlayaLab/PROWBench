# Evaluating your own method

This guide runs every evaluation stage on the videos generated by your method and builds the table row of the paper.
Text in angle brackets (`<...>`) is a placeholder. Commands marked [GPU] need a GPU.

From the repository root, set the paths (absolute, without spaces) and enter `eval/`. Use one `WORK` directory per
dataset, method and representation:

```bash
export PROWBENCH="$PWD"
export DATA="$PROWBENCH/prowbench-eval-data"
export WORK="$PROWBENCH/eval/results/verified_ff_40/my_model/mixed"
mkdir -p "$WORK"
cd "$PROWBENCH/eval"
export PYTHONPATH="$PWD"
```

`DATA` is the directory created by the [Quick start](../README.md).

## 1. Environments

| environment | used for | software |
|---|---|---|
| eval | all stages except the two below | Python 3.11, PyTorch 2.10.0, Transformers 5.17.0 |
| quality | section 4.6 (VBench, warp error, CLIP-Score) | Python 3.11, PyTorch 2.11.0, VBench 0.1.5 |
| ViPE | camera estimation | ViPE 1.2.0 |

```bash
# eval environment, from $PROWBENCH/eval
python3.11 -m venv .venv-eval && source .venv-eval/bin/activate
pip install torch==2.10.0 torchvision==0.25.0 --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt -r requirements-models.txt
deactivate

# quality environment, from $PROWBENCH/eval
python3.11 -m venv .venv-quality && source .venv-quality/bin/activate
pip install torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements-quality.txt
deactivate

# ViPE environment (official installation from source: conda for the CUDA toolchain, uv for the Python environment)
git clone --branch v1.2.0 https://github.com/nv-tlabs/vipe.git <vipe checkout> && cd <vipe checkout>
conda env create -f envs/cu128.yml && conda activate cu128
UV_PYTHON_PREFERENCE=only-managed uv sync   # builds the CUDA extension into <vipe checkout>/.venv
conda deactivate && cd $PROWBENCH/eval
```

Run the commands from `$PROWBENCH/eval` in the eval environment (`source .venv-eval/bin/activate`); section 4.6 runs in the
quality environment (`source .venv-quality/bin/activate`). The first ViPE run downloads its models and needs internet
access. MEt3R (multi-view dataset only) is installed following [its instructions](https://github.com/mohammadasim98/met3r).

Models: `facebook/sam3` (request access on [Hugging Face](https://huggingface.co/facebook/sam3), then `hf auth login`),
`facebook/sam2.1-hiera-large` and `Qwen/Qwen3.6-27B` (judge; needs a GPU with about 80 GB free) are downloaded from
Hugging Face on first use; VBench downloads its weights into `VBENCH_CACHE_DIR` on its first run. Download the RAFT and
CLIP weights into a directory `<weights>`:

```bash
mkdir -p <weights> && cd <weights>
wget https://dl.dropboxusercontent.com/s/4j4z58wuv8o0mfz/models.zip && python -m zipfile -e models.zip .
wget https://openaipublic.azureedge.net/clip/models/40d365715913c9da98579312b702a82c18be219cc2a73407c4526f58eba950af/ViT-B-32.pt
cd $PROWBENCH/eval
```

`ffmpeg` must be on `PATH` (or set `FFMPEG`). Select GPUs with `CUDA_VISIBLE_DEVICES` and keep `--device cuda:0`.

## 2. Generated videos

Generate one video per view listed in `$DATA/<dataset>/samples.jsonl` and store it as

```
model_output_video/<dataset>/<method>/<episode>/<camera>/<representation>/video.mp4
```

for example `model_output_video/verified_ff_40/my_model/dv200-001-city-crossing/follow/mixed/video.mp4`.
`<representation>` is the proxy you conditioned on (`white`, `mixed` or `colored-obb`). Store another run of the same
method under another `<method>` name.

Videos must cover the whole clip (5 s; 30 s for `long_horizon`), at any resolution and frame rate. If your method crops the proxy frame, add `--crop center` or `--crop x,y,w,h` (in proxy pixels) to
`make_samples`.

## 3. Outputs

Per-sample results are written to `$WORK/metrics/`, `$WORK/judge/` and `$WORK/mv/`, the table row to `$WORK/table.json`.

## 4. Five-second datasets, step by step

Example for `verified_ff_40`; replace the dataset name for `unverified_ff_90` and `gunfight`.

**4.1 Ground truth**

```bash
python -m prowbench_eval.gt_export --dataset $DATA/verified_ff_40 --out $WORK/gt --first-person-filter auto
```

**4.2 Samples**

```bash
python -m prowbench_eval.make_samples --dataset $DATA/verified_ff_40 \
    --videos $PROWBENCH/model_output_video/verified_ff_40/<method> --method <method> \
    --representations <representation> --out $WORK/samples.jsonl --gt-dir $WORK/gt --work $WORK
```

**4.3 Tracking [GPU]**

```bash
python -m prowbench_eval.detect_track --jobs $WORK/detect_jobs.json --tracker sam3 --model facebook/sam3 \
    --sam3-score-thresh 0.2 --sam3-prompts '{"obstacle": "barricade", "cable": "tow cable", "weapon": "rifle"}' \
    --sam3-fallback sam2 --sam2-model facebook/sam2.1-hiera-large --grid-hz 8 --device cuda:0
```

**4.4 Camera estimation [GPU]**

```bash
<vipe checkout>/.venv/bin/python -m prowbench_eval.estimate_camera --jobs $WORK/camera_jobs.json --backend vipe --vipe-root <vipe checkout> \
    --vipe-pipeline pose_only --device cuda:0
```

**4.5 Entity and camera metrics**

```bash
while read -r row; do
  key=$(python -c 'import json,sys; print(json.loads(sys.argv[1])["sample_id"].replace("/", "__"))' "$row")
  ep=$(python -c 'import json,sys; r=json.loads(sys.argv[1]); print(r["episode"] + "/" + r["camera"])' "$row")
  fps=$(python -c 'import json,sys; print(json.loads(sys.argv[1])["fps"])' "$row")
  python -m prowbench_eval.metric_entity --gt $WORK/gt/$ep.json --prediction $WORK/preds/$key.json --sample "$row" \
      --out $WORK/metrics/$key.entity.json
  python -m prowbench_eval.metric_camera --gt $WORK/gt/$ep.json --pred-traj $WORK/camera_traj/$key.json --pred-fps $fps \
      --protocol cami2v --out $WORK/metrics/$key.camera.json
done < $WORK/samples.jsonl
```

**4.6 Visual quality, warp error and CLIP-Score [GPU, quality environment]**

```bash
python -m prowbench_eval.metric_vbench prepare --samples $WORK/samples.jsonl --out-dir $WORK/vbench_input
export VBENCH_CACHE_DIR=<vbench weight cache>
vbench evaluate --videos_path $WORK/vbench_input --mode=custom_input --output_path $WORK/vbench_out \
    --load_ckpt_from_local true --dimension "imaging_quality aesthetic_quality"
vbench evaluate --videos_path $WORK/vbench_input --mode=custom_input --output_path $WORK/vbench_ms_out \
    --load_ckpt_from_local true --dimension "motion_smoothness"
python -m prowbench_eval.metric_vbench summarise --vbench-json $WORK/vbench_out/<name>_eval_results.json \
    --mapping $WORK/vbench_input/mapping.json --out-dir $WORK/vbench
python -m prowbench_eval.metric_vbench summarise --vbench-json $WORK/vbench_ms_out/<name>_eval_results.json \
    --mapping $WORK/vbench_input/mapping.json --out-dir $WORK/vbench_ms
python -m prowbench_eval.metric_temporal --samples $WORK/samples.jsonl --out-dir $WORK/metrics --raft <weights>/models/raft-things.pth --device cuda:0
python -m prowbench_eval.metric_clipscore --samples $WORK/samples.jsonl --out-dir $WORK/metrics --index $DATA/verified_ff_40 \
    --clip <weights>/ViT-B-32.pt --device cuda:0
```

`<name>_eval_results.json` is the file that VBench writes into its output directory.

**4.7 Interaction Success Rate and Logic-Render Alignment [GPU]**

```bash
python -c 'import json, sys; json.dump(dict(dataset=sys.argv[1], output=sys.argv[2]), open(sys.argv[3], "w"))' \
    "$DATA/verified_ff_40" "$WORK/registry" "$WORK/registry.json"
python -m prowbench_eval.event_registry --config $WORK/registry.json
python -m prowbench_eval.windowed_judging interaction --samples $WORK/samples.jsonl --gt-dir $WORK/gt \
    --protocol protocol/verified_ff_40/settings.json --registry $WORK/registry/registry.json \
    --visual-events protocol/verified_ff_40/events.json --out $WORK/judge
python -m prowbench_eval.windowed_judging alignment --samples $WORK/samples.jsonl --gt-dir $WORK/gt \
    --protocol protocol/verified_ff_40/settings.json --descriptions protocol/verified_ff_40/descriptions.json --out $WORK/judge
```

**4.8 Table**

```bash
python -m prowbench_eval.report_tables rows --samples $WORK/samples.jsonl --metrics-dir $WORK/metrics \
    --judge-dir $WORK/judge --vbench $WORK/vbench/per_sample.jsonl --vbench-motion $WORK/vbench_ms/per_sample.jsonl \
    --out $WORK/rows.jsonl
python -m prowbench_eval.report_tables table --rows $WORK/rows.jsonl --dataset $DATA/verified_ff_40 --out $WORK/table.json
```

The row is written to `$WORK/table.json`. To compare methods in one table, pass the `rows.jsonl` files of all of them to
`--rows`.

Table:

```bash
WORK="$WORK" python - <<'EOF'
import json, os, sys
from pathlib import Path
from prowbench_eval import long_horizon_tables

work = Path(os.environ["WORK"])

def read(path):
    return json.loads(path.read_text()) if path.exists() else None

recordings = []
for line in (work / "samples.jsonl").read_text().splitlines():
    s = json.loads(line)
    key = s["sample_id"].replace("/", "__")
    isr, lra = read(work / "judge" / f"{key}.interaction.json"), read(work / "judge" / f"{key}.alignment.json")
    recordings.append(dict(
        entity=read(work / "metrics" / f"{key}.entity.json"), memory=read(work / "metrics" / f"{key}.memory.json"),
        state=read(work / "metrics" / f"{key}.state.json"), camera=read(work / "metrics" / f"{key}.camera.json"),
        isr=isr["summary"]["interaction_success"] if isr else None,
        lra=lra["summary"]["dynamic_checklist"] if lra else None))
reps = {json.loads(line)["representation"] for line in (work / "samples.jsonl").read_text().splitlines()}
if len(recordings) != 10 or len(reps) != 1:
    sys.exit(f"expected the 10 long_horizon recordings of one representation, got {len(recordings)} rows of {sorted(reps)}")
(work / "table.json").write_text(json.dumps(long_horizon_tables.method_row(recordings), indent=1))
EOF
```

## 7. Re-running and resuming

Tracking, camera estimation, warp error, CLIP-Score, VBench preparation, `windowed_judging` and `multiview_eval` skip
samples whose results exist, so an interrupted stage resumes when the same command is run again; the other commands
recompute their outputs. Delete the outputs of a stage before running it with other inputs. Judge answers are cached in
`$WORK/judge/.judge_cache` and `$WORK/mv/appearance/.judge_cache`; to judge a sample again, delete its result file and
the cache.

## 8. Protocol files

`protocol/<dataset>/` holds the settings of the reported scores and the questions of the judges
([protocol/README.md](protocol/README.md)); the commands above use them as given.

## 9. Worked example [CPU]

This example checks the installation on one view, using the released proxy video as the generated video and the
recorded boxes and camera in place of the tracker and the camera estimator:

```bash
export PROWBENCH_EVAL_DURATION=5 WORK="$PROWBENCH/eval/results/worked_example"; mkdir -p "$WORK"
DS=verified_ff_40; EP=dv200-001-city-crossing; CAM=follow; REP=colored-obb
python -m prowbench_eval.gt_export --dataset $DATA/$DS --out $WORK/gt --episodes $EP --first-person-filter auto
mkdir -p $WORK/videos/$EP/$CAM/$REP
cp $DATA/$DS/episodes/$EP/$CAM/$REP/video.mp4 $WORK/videos/$EP/$CAM/$REP/video.mp4
python -m prowbench_eval.make_samples --dataset $DATA/$DS --videos $WORK/videos --method proxy \
    --out $WORK/samples.jsonl --gt-dir $WORK/gt --work $WORK
# oracle tracks and trajectory from the ground truth (stand-ins for detect_track and estimate_camera)
python - "$WORK" <<'EOF'
import json, sys
from pathlib import Path
work = Path(sys.argv[1])
s = json.loads((work / "samples.jsonl").read_text().splitlines()[0])
gt = json.loads((work / "gt" / s["episode"] / (s["camera"] + ".json")).read_text())
ids = {e: i for i, e in enumerate(gt["entities"])}
frames = [dict(frame=f["frame"], detections=[dict(track_id=ids[e], label=gt["entities"][e]["label"], score=1.0, box=b["box"])
                                             for e, b in f["boxes"].items() if b.get("visible") and b.get("box")])
          for f in gt["frames"]]
key = s["sample_id"].replace("/", "__")
(work / "preds").mkdir(exist_ok=True)
(work / "preds" / f"{key}.json").write_text(json.dumps(dict(schema="prowbench.tracks.v1", width=s["width"], height=s["height"],
                                                            fps=s["fps"], frame_count=s["frame_count"], frames=frames)))
traj = [dict(frame=c["frame"], position=c["position"], quaternion=c["quaternion"]) for c in gt["camera_trajectory"]]
(work / "camera_traj").mkdir(exist_ok=True)
(work / "camera_traj" / f"{key}.json").write_text(json.dumps(dict(schema="prowbench.traj.v1", fps=s["fps"], frames=traj)))
EOF
KEY=${EP}__${CAM}__${REP}; SAMPLE="$(head -n 1 $WORK/samples.jsonl)"
python -m prowbench_eval.metric_entity --gt $WORK/gt/$EP/$CAM.json --prediction $WORK/preds/$KEY.json --sample "$SAMPLE" \
    --out $WORK/metrics/$KEY.entity.json
python -m prowbench_eval.metric_camera --gt $WORK/gt/$EP/$CAM.json --pred-traj $WORK/camera_traj/$KEY.json --pred-fps 30 \
    --protocol cami2v --out $WORK/metrics/$KEY.camera.json
python -m prowbench_eval.metric_vbench prepare --samples $WORK/samples.jsonl --out-dir $WORK/vbench_input
python -c 'import json, sys; json.dump(dict(dataset=sys.argv[1], output=sys.argv[2]), open(sys.argv[3], "w"))' \
    "$DATA/$DS" "$WORK/registry" "$WORK/registry.json"
python -m prowbench_eval.event_registry --config $WORK/registry.json
python -m prowbench_eval.report_tables rows --samples $WORK/samples.jsonl --metrics-dir $WORK/metrics --out $WORK/rows.jsonl
python -m prowbench_eval.report_tables table --rows $WORK/rows.jsonl --out $WORK/table.json
```

The last command prints `iou` 1.0, `cerr` 0.0 and `rot`, `trans`, `cammc` 0.0; the other columns are `null`.
